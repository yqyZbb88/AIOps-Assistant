## 项目定位与能力

项目把少量 Linux 主机的指标、告警、诊断、处置审批和历史记录整合到一个控制台。
Prometheus 提供指标，Alertmanager 推送告警，Assistant 组织业务，SQLite 保存历史；
Grafana 提供另一套监控图表入口。项目没有自行实现指标采集或时序数据库。

| 能力 | 当前行为与交接关注点 |
|---|---|
| 主机监控 | 显式主机注册表，17 个内置指标；通过固定指标目录查询，不能提交任意 PromQL |
| 巡检 | 按主机串行巡检，有主机数、查询数和时间预算；正常轮次写日志，异常轮次另入库 |
| 问答 | 无模型时保留关键词问答；配置模型后可调用受控工具，会话绑定主机和身份 |
| 告警 | 接收 Alertmanager webhook，匹配规则；无匹配规则时可生成 AI 分析建议 |
| SSH 诊断 | 管理员定义只读命令目录，逐主机授权；服务端解析目标和凭据 |
| 写操作 | 规则自动处置与 Agent 人工审批是两条独立路径，均保留执行与审计记录 |
| 管理 | 控制台提供结构化配置、主机新增、热应用与历史查询，不是通用 YAML 编辑器 |

当前适合一个 Prometheus/Alertmanager、一个 Assistant 进程、一个 worker 和少量用户。
不支持多个实例共享运行目录。新增主机只登记目标，不负责安装 Exporter 或部署远程服务。
Compose 自带的 Node Exporter 默认反映其 Linux 容器运行环境，不能视为完整的宿主机监控。

## 业务链路

### 1. 身份、主机与监控

Token 映射为服务端身份，管理员与审批人分别授权。业务数据通过 API 获取，
`/console` 的公开静态页面本身不包含受保护业务数据。所有业务接口始终验证 Token，鉴权开关已删除。普通用户默认无主机权限，
由管理员按稳定身份授权。管理员可访问所有主机，但私有会话仍只能由创建者访问。

主机以稳定的 `host_id` 标识，关联 Prometheus 的 `job/instance` 及可选 SSH 凭据引用。
会话、诊断、审批和执行记录沿用这个主机归属；不能把一个已有会话切换成另一台主机。
主机新增时默认不授予 SSH 命令权限，SSH 检查只验证握手认证，不执行命令。

指标查询走固定目录和指定目标。无数据、目标不可达、数据过期与实际异常需要分别
判断；历史异常记录也不等于当前健康状态。详细操作见 [使用指南](guide.md) 和
[只读排障](troubleshooting.md)。

### 2. 告警与规则自动处置

```text
Alertmanager → POST /alert → 解析主机 → 匹配规则
                                      ├─ 命中：核验开关、命令和主机授权 → 自动处置
                                      └─ 未命中：可选 AI 分析建议
                           → 告警、建议、处置与执行记录
```

规则依据告警名和明确主机目标匹配；不能对无法确定目标的告警随意执行命令。
自动执行需要全局开关、规则开关、命令启用及该主机授权同时满足。
**规则自动处置不走 Agent 的人工审批**，接手者必须单独核对这条路径的授权与幂等保护。
恢复态告警不会作为新的自动处置触发。

告警处理与持久化失败可能向上游返回失败，Alertmanager 可以重试；幂等记录用于约束
重复处置。不能为了减少 webhook 错误而吞掉失败或删除执行状态。
Webhook 身份和响应语义见 [鉴权说明](auth.md) 与 [API 参考](api.md)。

### 3. 问答、诊断与人工审批

用户在指定主机会话中提问，服务端选择关键词问答或 Agent。Agent 的监控、诊断和动作
工具从受控目录构建，目标和 SSH 凭据不由用户或模型自由输入。

写命令先生成审批申请，冻结主机、动作和参数；审批轮次成功保存后，才允许有权限的
审批人决定。批准后恢复 Agent 执行，结果进入统一执行记录；拒绝、过期或取消不执行。
一个动作完成后可能出现下一条申请，下一条仍需独立保存和审批。

审批记录可以持久化，待审批对象和 LangGraph checkpoint 位于当前进程。
**服务重启后不能继续执行旧申请**。执行结果为 `unknown` 时，要核对目标状态和审计
证据，不能直接重发写命令。具体状态和操作见 [数据库说明](database.md)、
[控制台说明](console.md) 和 [只读排障](troubleshooting.md)。

### 4. 配置应用

管理页提交完整草稿和文件 revision；服务端验证字段、跨文件引用和候选运行快照，
备份变更文件后写回，并切换后续请求使用的快照。已开始的读请求可以用旧快照完成。
存在业务写操作、未决审批或无法核对审批状态时，配置应用会拒绝并返回 409。

页面外修改运行 YAML 后仍需应用磁盘配置；部署环境密钥、Compose 发布端口、SQLite/日志路径
等需要重启。单文件替换是原子的，多文件没有跨文件或断电原子性，写锁也不跨进程。
模型配置整组优先于环境；清除页面密钥不会回退。新部署模型地址和名称为空，
高级输出长度只发送所选参数。模型保存不访问网络，连接测试由管理员显式触发。
详见 [架构说明](architecture.md) 与 [配置生效说明](configuration.md#十一字段生效与重启)。

## 部署交接

仅提供容器运行，宿主机需要 Docker 和 Compose 2.24+。独立 test 镜像包含 Python 3.13
与 Node 22，CI 在容器内执行回归；生产镜像不安装测试依赖。控制台无前端构建流程。

| 服务 | 作用 | 默认发布端口 |
|---|---|---|
| `init` | 一次性初始化；成功后 `Exited (0)` 是正常状态 | 无 |
| `assistant` | 单 worker API、控制台和业务调度 | 8000 |
| `prometheus` | 指标抓取、查询与告警规则 | 9090 |
| `alertmanager` | 告警分组和 webhook 投递 | 9093 |
| `node-exporter` | 默认演示监控目标 | 9100 |
| `grafana` | 图表与看板 | 3000 |

端口默认绑定部署机 `127.0.0.1`，远程浏览器需隧道或另行部署访问入口。
初始化先准备配置与凭据；Prometheus 就绪后启动 Assistant，Assistant 就绪后启动
Alertmanager。首次操作按 [快速入门](quickstart.md)，完整生命周期按
[部署与升级](deployment.md)。`--wait-timeout` 是服务就绪等待，不是镜像拉取或构建的总超时。

交付部署环境时必须记录：源码修订和未提交差异、镜像标识、Compose 项目名、运行目录、
端口、持久化卷、是否使用外部 Prometheus、主机/凭据引用关系及备份恢复位置。
这些信息缺一时，不应假定换目录运行就能找到原数据。

迁移应明确选择“全新测试部署”还是“恢复原部署状态”：前者使用独立项目名、运行目录
和端口；后者需要源码、运行目录与数据卷的一致备份，并核对新机器网络和目标地址。
只复制源码不会带走会话、Token、Grafana 数据或监控历史。

Docker registry 超时、连接拒绝属于镜像获取阶段的基础设施故障，不能据此判断
Assistant 业务启动失败。代理和镜像源属于每台主机的 Docker 配置，复制项目不会复制
这些设置；也不能将健康检查或单次镜像拉取成功当成整栈验收。

## 配置与数据交接

### 配置的权威来源

| 来源 | 作用与注意点 |
|---|---|
| 根 `.env` | Compose 参数与可选模型 配置，不提供业务身份 |
| `deploy/templates/assistant/` | 新 Compose 部署模板，随源码发布；修改模板不覆盖已有部署 |
| `.runtime/config/` | Compose 实际运行配置，管理页保存写这里 |
| `.runtime/compose.env` | 持久化凭据来源及可选环境值；不作为 Compose 的 `--env-file` |
| `.runtime/deployment.json` | 初始化来源、凭据检查点、完成状态和配置迁移版本 |
| `.runtime/secrets/`、`.runtime/alertmanager/`、`.runtime/grafana/` | 服务专用派生凭据，分别挂入所需服务 |
| `.runtime/assistant-data/admin-credentials/` | 页面 SSH、Token、模型持久凭据；受限目录 |
| `deploy/` 下监控组件目录 | Compose 直接挂载的公共组件配置 |

`AIOPS_RUNTIME_DIR` 可改变 `.runtime/` 位置，后续命令必须保持相同值。
根 `.env` 与进程环境影响 Compose 参数和可选模型 设置；Compose 的业务身份使用
初始化生成的部署凭据与页面管理 Token。凭据通过独立安全渠道交付，不写在本文。
模板只用于首次初始化；运行 YAML 与页面凭据是持久来源；服务专用文件单向派生。
手工改派生文件不会反向同步，Grafana 页面改密以其数据库为准。
旧部署请按 [一次性配置迁移](deployment.md#一次性配置迁移) 执行，禁止直接套模板覆盖。

七份 YAML 分工：`settings.yaml` 管开关和运行限制，`hosts.yaml` 管主机与权限引用，
`metrics.yaml` 管指标，`rules.yaml` 管自动处置，`actions.yaml` 管规则写命令，
`diagnostics.yaml` 管只读诊断，`agent_actions.yaml` 管需审批的 Agent 写命令。
字段与约束见 [配置指南](configuration.md)，身份与轮换见 [鉴权说明](auth.md)。

Prometheus 主配置与动态目标文件是不同格式。目标文件会被 managed 主机登记维护，
手工添加抓取目标不会自动在 Assistant 注册主机。路径和生效方式见
[Prometheus 主配置与目标列表](configuration.md#compose-的-prometheus-主配置与目标列表)。

### 持久化与恢复边界

| 状态 | 保存位置 | 交接要求 |
|---|---|---|
| 会话、告警、审批决策、执行与异常巡检 | SQLite，Compose 位于运行目录 `assistant-data/` | 按 schema 7 核对；在线使用 SQLite 备份或停服务后完整复制 |
| 审计和正常巡检 | `assistant-logs/` | 单独交付保留策略，不将日志当成数据库替代品 |
| 配置及配置备份 | `config/`、`assistant-data/` 下的配置备份 | 配置备份不是 SQLite 备份 |
| 动态目标与演示指标 | `prometheus-targets/`、`textfile/` | 与运行配置一起核对，迁移后检查目标地址 |
| 时序、告警管理和图表数据 | Prometheus、Alertmanager、Grafana 命名卷 | 独立备份，保留项目与卷对应关系 |
| 待审批执行线程、SSH 检查票据 | 进程内存 | 重启失效，不能凭历史审批记录恢复执行线程 |

初始化保留既有配置、有效凭据和数据。派生凭据缺失可由源凭据恢复；已记录凭据的部署
丢失 `compose.env` 时应恢复备份，不能删除检查点让它重新生成身份。
`docker compose down` 保留卷，`down -v` 会删除监控数据卷。
SQLite 备份、迁移和恢复步骤统一见 [数据库说明](database.md)。

## 修改与验证

运行依赖在 `requirements-runtime.txt`，开发/测试依赖在 `requirements.txt`，
`requirements-lock.txt` 固定已验证版本，属于约束快照。变更依赖需重新验证安装和运行，
不能只修改一个版本号。代码、配置、数据库和文档同步要求见 [贡献约定](../CONTRIBUTING.md)。

| 修改方向 | 最需要保护的行为 | 相关测试入口 |
|---|---|---|
| 主机与指标 | 不串主机，固定目录、目标和查询预算 | `test_multi_host_boundaries.py`、`test_prometheus_monitor.py`、`test_metrics_config.py` |
| 规则处置 | 授权、唯一目标、幂等与执行记录 | `test_rule_engine.py`、`test_remediation_guard.py`、`test_execution_store.py` |
| 会话与审批 | 保存失败不执行，旧申请不重放，连续审批正确 | `test_chat_history.py`、`test_api_approvals.py`、`test_agent_actions_hitl_graph.py` |
| 配置和登记 | revision、写操作冲突、候选快照与失败回滚 | `test_admin_config.py`、`test_hosts_config.py`、`test_config_loader.py` |
| SSH 与命令 | 主机密钥、参数范围、超时、输出限制和连接释放 | `test_ssh_security.py` 及各命令目录测试 |
| SQLite | 原子事务、迁移一致、无孤立消息、审批历史保护 | `test_sqlite_db.py`、`test_session_store.py`、`test_history_store.py` |
| 控制台 | 旧异步响应不覆盖新主机/身份，安全 DOM、重复提交 | `console_ui.test.cjs`、`test_console_ui_runtime.py` |
| 部署 | 幂等初始化、凭据保留、重建后数据不丢 | `test_deployment.py`、`test_stack.py`、`compose_smoke.py` |

完整测试命令和隔离要求见 [容器测试与验收](testing.md)。离线回归使用合成身份和模拟
外部系统，不访问真实模型、SSH、数据库或日志。Node 语法和交互测试应按该专题执行。

CI 的 `test` 任务验证依赖、编译与 pytest；`deployment-smoke` 任务构建临时 Compose 栈，
检查 webhook 和重建持久化，再清理该隔离栈。任务存在不代表当前修订已经运行通过，
交接时须附实际结果。浏览器、真实模型和 SSH 仍需相应环境的验收证据。

### 必须保持的约束

- 用户和模型不能提交任意 PromQL、Shell、SSH 目标或凭据。
- Agent 写命令始终需人工审批；规则自动处置的独立授权、审计和幂等不能移除。
- SSH 拒绝未知主机密钥；命令来自模板，参数有完整匹配和范围校验。
- 不通过增加 worker 绕开进程内配置锁和审批状态，不让两个实例共享运行目录。
- 变更数据库递增 schema 并保留旧迁移；涉及父子数据的清理必须在事务内完成。
- 自定义会话 Store 要实现完整历史中的待审批核验，不能用界面展示窗口代替。
- 输出需限制长度并脱敏；现有脱敏不意味着历史数据库或日志已被重新清洗。
- 源码、镜像和测试输出不包含真实凭据、运行数据库或运维数据。

## 验收与接手顺序

### 接手第一天

1. 确认源码修订、未提交差异、版本与 schema；区分代码交付和某台机器的运行状态。
2. 阅读本文与架构说明，明确规则自动处置、Agent 审批和管理权限三个边界。
3. 接收环境清单及凭据的安全交付渠道，确认实际配置来源、项目名、端口和备份位置。
4. 在独立运行目录完成新部署，观察 `init` 成功退出和常驻服务健康，再连接控制台。
5. 选择目标主机，查看指标、创建会话并验证无模型的问答路径。

### 接手后的集成验收

1. 按测试专题完成隔离的离线回归和 Compose 冒烟检查，保存具体修订与结果。
2. 验证匿名、普通用户、管理员和审批人的权限；确认业务与 webhook 的身份映射符合各自用途。
3. 在测试主机验证告警主机归属和幂等，分别验收规则自动处置与 Agent 审批。
4. 需要 AI/SSH 时，先验收模型连接和只读诊断，再对最小授权的测试动作验收批准、拒绝、
   重复请求及重启边界；禁止直接对真实业务主机做演示故障或写动作练习。
5. 验证配置热应用和冲突拒绝，重建服务后核对 Token、配置和会话仍存在。
6. 从备份恢复到独立环境，核对 SQLite、命名卷、主机引用和登录身份。

以上是接手验收要求，不是已经通过的声明。每项应记录环境、修订、执行人、日期、结果
和未覆盖范围；缺少真实外部环境时明确列为未验收。

## 2026-10-09 会话隔离与用户主机权限维护

根因来自实际持久化配置与数据库核对：旧运行配置 auth.enabled=false，原 require_auth
直接返回 None，未解析浏览器提供的 Token；会话所有者检查又把 None 视作可信内部调用，
因此不同 Token 仍进入相同匿名视图。当时没有运行容器，诊断证据来自磁盘配置、数据和代码，
不是对故障发生时在线请求的追溯。后续已在隔离容器验证含该旧开关的配置迁移与身份隔离。

业务 API 现在始终校验 Token；主机访问由 auth.host_access 绑定稳定身份，普通用户默认拒绝，
管理员隐式访问所有主机，但私有会话仍仅创建者可读改删/聊天。会话 API、聊天、监控、告警、
巡检、执行记录及审批均检查服务端权限；无 host_id 的记录查询也按授权主机过滤后排序限量。
控制台新增“用户主机授权”，诊断/写命令白名单和审批角色独立，Token 轮换保留权限。

配置使用原 revision/备份/原子写入/快照切换；写业务或未决审批存在时 409，不应误报撤权成功。
审批额外检查申请人与决策人均有主机权限。HTTP 聊天无法验证持久化会话时 503，不回退到
默认主机。init 会备份后移除 auth.enabled，不自动给普通用户所有主机权限。
实际运行目录已迁移，凭据哈希和其余数据库表记录数保持；未启动带真实模型/SSH 的业务栈。

经用户明确选择，先备份、再清除了确认的 3 个无归属会话及关联消息/审批决策；
其余历史保留。受限备份为 .runtime/backups/pre-host-access-20261009.zip，
迁移前设置另备份至 assistant-data/config-backups/pre-host-access-settings.yaml。
匿名会话不会由常规升级自动删除或推断归属。

仅有第三方 Starlette/AnyIO 弃用警告。隔离 Compose 双用户/双主机通过，
覆盖跨用户读取、聊天、改名、删除拒绝、跨主机 9 类查询拒绝、Token 轮换/撤销、
权限撤销/恢复，以及整栈重建后身份、ACL 和私有聊天恢复。
17 项即时/趋势 API、真实 Alertmanager→Assistant 投递、页面 SSH/模型配置持久化、

管理员身份的严格校验及原 revision/写操作/审批并发边界保持。
