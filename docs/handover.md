# 项目交接清单

本文用于接手部署和代码。整体架构、调用链及设计原因独立保存在
[架构与实现详解](architecture.md)。环境、人员、凭据及历史执行记录通过受控渠道交付，
不写入发布文档。

## 阅读路线

先读 [README](../README.md)和[快速入门](quickstart.md)，确认能力与运行方式；
开发者接着读架构详解和[贡献约定](../CONTRIBUTING.md)，维护者接着读
[部署与升级](deployment.md)、[鉴权说明](auth.md)与[数据库说明](database.md)。
其余任务通过[文档导航](README.md)定位，参数仅在相应专题维护。

## 接手时必须确认

| 事项 | 交付内容 | 核验方法 |
|---|---|---|
| 版本 | Git 提交、镜像标签/摘要、未提交变更 | 与运行容器、代码版本核对 |
| 部署边界 | Compose 项目名、运行目录、端口、代理 | 核对状态和实际挂载；内部地址私下交付 |
| 配置 | 七份 YAML、根环境输入、持久 compose.env | 检查来源及 revision，不能用模板覆盖运行配置 |
| 身份与权限 | 管理员、webhook、审批角色、主机 ACL | 验证角色与越权拒绝，Token 通过密钥渠道交付 |
| 监控 | 主机 job/instance、Exporter 负责人 | Targets、即时/趋势与活动告警 |
| 写权限 | 规则总开关、单规则、动作目录、主机白名单 | 核对两条写路径、审批模式及执行记录 |
| 凭据 | 页面状态和 SSH 版本资产、轮换方式 | 检查引用，真实连接由获授权人员显式测试 |
| 数据 | SQLite、日志、三个监控命名卷 | 实际路径、保留策略和最近记录 |
| 恢复 | 同批代码/配置/凭据/数据备份、校验及回退副本 | 独立恢复演练和恢复后业务验收 |
| 验收 | 本次报告、失败/跳过项、待核实事项 | 不将旧报告或探针等同本次业务验收 |

## 接手顺序

1. 只读核对版本、项目名、运行目录、服务状态与日志，确认连接正确环境。
2. 使用自己的身份登录，核对主机范围、会话归属、17 项指标及告警来源。
3. 确认规则/Agent 写开关、审批角色、未决申请及 unknown/running 执行，先处理不确定状态。
4. 确认备份完整且可恢复，再安排升级；旧配置迁移只能停栈后显式执行。
5. 在独立栈按[测试流程](testing.md)运行离线、集成、页面与已启用能力验收。
6. 把实际结果、负责人及遗留事项记录到组织系统或私有交接包。

## 必须保持的约束

当前版本 0.6.2、SQLite schema 8、单进程单 worker，不通过多 worker 绕过配置锁、审批
和调度前提。业务鉴权不可关闭；管理员不能读取他人私有会话，也不自动成为审批人。
登记主机、监控可达和 SSH 认证通过不自动授予写权限。

重启保留持久会话与历史，但不保留审批 checkpoint、最近告警缓冲和 SSH 票据。
未决申请不自动补执行，unknown 需核对远端事实；有限 TTL 幂等不是无限期 exactly-once。
完整故障语义见架构详解。

## 验收与待核实项

至少覆盖身份/主机隔离、监控、webhook、重建持久化、配置冲突与恢复。启用模型、SSH
或写命令的部署需真实闭环，不为测试扩大生产权限。恢复时间/数据丢失目标、现场并发与
容量、代理 TLS、浏览器兼容性、满盘/断电场景均需现场核实；未执行项明确原因及责任人。
发布文档不保留某台机器的测试数量或维护日期。

## 重点交接约束

规则抢占与执行审计须覆盖 SQLite 共库的生产分支。SSH 固定加载器、命令兼容性及
unknown 语义见[架构说明](architecture.md#ssh-与命令安全)；升级时核对现场 sudo 策略。
旧空失败详情不能反推退出码，不回写为成功或自动补执行。

- 当前身份取自 `GET /identity`，右上角显示服务端身份及角色；401 清除旧身份与业务视图。
- 审批进度区分持久决策、动作执行和 AI 反馈；审批 POST 或进度查询超时均不能自动重放。
- 主机登记删除与停止托管采集分别确认。先撤销用户主机授权、移除关联规则，并处理未决审批及运行/未知执行；历史不随主机登记删除。
- 仅 managed 模式指定 file_sd 文件可由项目修改；外部 Prometheus 只删除登记。目标停止后等候 30 秒发现刷新，旧样本按 Prometheus 保留策略处理。
- SSH 编辑会定位到表单并显示当前编辑 ID，留空保留敏感材料；不接受任意文件路径，不自动信任主机密钥。部署文件中的凭据仍只读，可创建新页面凭据再切换关联。
- schema 8 保存新申请冻结摘要及生命周期。审批通过与执行结果分别查询；历史归属、申请时间或作废原因无法证明时显示未知，主机归属未知的旧行不向用户开放。
- [查询对照表](metric-queries.md)覆盖 17 项指标及所有入口；CPU rate 统一为 5 分钟，默认磁盘 warning/告警统一为 80%。Grafana 仪表盘由目录生成。
- 代码变更不会替维护者更新实际部署。升级前同批备份配置/凭据/数据库；v8 数据库不能直接交给仅支持 v7 的旧程序。验收方法见[测试说明](testing.md#控制台审批与执行的隔离验收)。
